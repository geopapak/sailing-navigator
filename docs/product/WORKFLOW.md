# Πώς δουλεύει η ομάδα (agents)

Από την ιδέα μέχρι την κυκλοφορία. Ο καθένας παραδίδει στον επόμενο· εσύ εγκρίνεις στα σημεία με ✋.

```
Εσύ ──► product-owner ──► business-analyst ──► sailing-ui-ux (αν θέλει οθόνη) ──► sailing-developer + sailing-server-developer ──► qa-tester ──► κυκλοφορία
          ✋ ναι/όχι           ✋ spec              ✋ πρωτότυπο                                                         ✋ deploy server
```

| Ρόλος | Agent | Τι κάνει | Τι παραδίδει |
| --- | --- | --- | --- |
| Product Owner | `product-owner` | Σε συμβουλεύει για κάθε πρόταση (αξία, κόστος, ρίσκο), κρατά όραμα και backlog, βάζει προτεραιότητες μαζί σου | γραμμή στο `BACKLOG.md`, απόφαση στο `DECISIONS.md` |
| Business Analyst | `business-analyst` | Αναλύει την εγκεκριμένη πρόταση πάνω στον υπάρχοντα κώδικα | spec στο `specs/P-xxx-*.md` με κριτήρια αποδοχής και εργασίες |
| UI/UX | `sailing-ui-ux` | Πρωτότυπο για κάθε νέα οθόνη ή μεγάλη αλλαγή | `design/<θέμα>-YYYY-MM/` προς έγκριση |
| App developer | `sailing-developer` | Εφαρμογή (`src/`), PWA, και η ρουτίνα κυκλοφορίας | κώδικας + tests, έκδοση, σημειώσεις έκδοσης |
| Server developer | `sailing-server-developer` | Worker, D1, λογαριασμοί, ασφάλεια, AI και κόστος του | κώδικας + tests, migrations, εντολές deploy για σένα |
| QA | `qa-tester` | Σχέδιο ελέγχου, αυτόματα tests, χειροκίνητος έλεγχος σε κινητό/θέματα/offline, έλεγχος ασφαλείας | αναφορά ΠΕΡΝΑΕΙ / ΔΕΝ ΠΕΡΝΑΕΙ |
| Κείμενα | `copywriter` | Όλα τα κείμενα που διαβάζει ο χρήστης· ιστιοπλοϊκή ορολογία με το γλωσσάρι και αναζήτηση στο web· ρωτά ή κρατά τον αγγλικό όρο όταν δεν βρει σίγουρο ελληνικό. Αλλάζει μόνο κείμενα | αλλαγμένα κείμενα, νέοι όροι στο γλωσσάρι, ερωτήσεις |
| Ειδικοί | `sailor`, `pdf-analyst` | Ιστιοπλοϊκή γνώση· ανάγνωση PDF με λιγότερα tokens | απαντήσεις/έλεγχοι όταν τους ζητηθούν |

## Πώς ξεκινάς
- Γράψε στη συνομιλία π.χ. «Πες στον product-owner: θέλω ειδοποίηση όταν αλλάζει ο άνεμος πάνω από 10°».
- Ή ζήτα όλη τη ροή: «Πέρασε την P-003 από BA, developers και QA».
- Οι agents φορτώνονται σε **νέα** συνεδρία μετά από αλλαγή τους.

## Κανόνες που ισχύουν για όλους
- Απαντούν στα ελληνικά.
- Ανάλυση κώδικα: πρώτα με τα εργαλεία του **Serena** (σύμβολα, αναφορές, σημειώσεις του project στο `.serena/`), όταν ο server τρέχει και είναι εγκεκριμένος· αλλιώς με Grep/Read. Το `.mcp.json` και το `.serena/` μένουν εκτός git.
- Καμία μεγάλη αλλαγή οθόνης χωρίς εγκεκριμένο πρωτότυπο.
- Κάθε κυκλοφορία: έκδοση στο `package.json`, σημειώσεις στο `src/releases.json`, `npm run changelog`, αναφορά για το αν έγινε deploy και με τι αποτέλεσμα.
- Deploy του server και migrations στην παραγωγή τα τρέχεις εσύ.
- Το repo είναι δημόσιο: όχι προσωπικά δεδομένα, όχι κλειδιά.

## Git
- Το `main` είναι ό,τι είναι (ή θα γίνει) live: κάθε push στο `main` ανεβάζει την εφαρμογή στο GitHub Pages.
- Κάθε δουλειά σε δικό της branch από το `main`: `feature/P-xxx-σύντομο-όνομα`, `fix/…`, `docs/…`. Όταν μια δουλειά πατά πάνω σε άλλη, το branch ξεκινά από εκείνο το branch (π.χ. η P-019 από την P-018).
- Commits μικρά και με σαφές μήνυμα (στα αγγλικά), με τα tests να περνούν.
- Συγχώνευση στο `main` με `git merge --no-ff`, αφού περάσουν `npm test`, `npm run typecheck` και `npm run build`.
- Push του `main` μόνο στην κυκλοφορία, μετά τις σημειώσεις έκδοσης. Αν η έκδοση θέλει νέο server ή migration, πρώτα τρέχει ο χρήστης `d1 migrations apply --remote` και `npx wrangler deploy`, και μετά γίνεται push της εφαρμογής.
- Κάθε κυκλοφορία παίρνει tag `vX.Y.Z`.
